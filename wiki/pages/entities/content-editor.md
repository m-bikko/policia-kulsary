# Редактор контента /edit

Страница `/edit` - вход по PIN-коду (один общий PIN на все лендинги), затем карта Казахстана со всеми лендингами и редактор каждого документа из [[content-model]]. UI на **ant-design v6** (тема в цветах сайта), интерфейс на трёх языках (QAZ/RUS/ENG, выбор хранится в cookie `jp_admin_lang`).

## Вход

- PIN - переменная окружения `ADMIN_PIN` (по умолчанию в `.env`: `123123`). Сравнение за постоянное время.
- После входа - httpOnly cookie `jp_admin_session`, подписанная HMAC-SHA256, срок 12 ч (продлевается при каждом сохранении).
- Секрет подписи - `ADMIN_SESSION_SECRET` или производная от PIN и service-ключа: **смена PIN разлогинивает все устройства**.
- Защита от перебора: 5 неверных попыток с одного IP → блок на 15 минут + задержка 0,8 с на каждую ошибку (счётчик в памяти процесса).
- Страница с `robots: noindex`.

## Дашборд `/edit` - карта

- Карточки «Общий шаблон» и «Портал» → `/edit/template`, `/edit/portal`.
- [[kz-map|Карта]] со статусами: золотой - опубликован, серый - черновик; счётчик «Опубликовано: N из 246». Клик по области - зум и список её районов (выбор в якоре адреса `/edit#atyrau`, работает «назад»), клик по району - его редактор.
- Справа: поиск по названиям на трёх языках (без учёта казахских букв), список областей с числом опубликованных лендингов, внутри области - лендинг департамента и районы со статусами.

## Документ `/edit/[...id]`

- Хлебные крошки «Карта / Область / Район», тип документа, кнопка назад к карте с приближенной областью.
- Лендинг: переключатель «Опубликован на сайте» (`setSiteStatusAction`, сразу `updateTag`), «Предпросмотр» (`/edit/preview/<id>?lang=kz|ru|en` - сохранённая версия, в том числе черновик, с баннером) и «Открыть на сайте» для опубликованных.
- По умолчанию у лендинга видны только его поля (`siteSchema` из `SITE_FIELDS`); переключатель «Все поля» открывает всю схему, чтобы заменить подписи шаблона только для этого лендинга.
- Наследование видно в полях: пустое поле показывает текст шаблона серым (placeholder), фото шаблона - полупрозрачно с меткой «Из шаблона», пустой список - «Используется общий список из шаблона (N)» + «Скопировать из шаблона и изменить». Внутри элементов списков наследования нет (списки берутся целиком).
- В шаблоне - предупреждение «Изменения общего шаблона сразу применяются ко всем лендингам».
- После входа возвращает на ту страницу, с которой просили PIN (`next`, только пути `/edit...`).

## Редактирование

- Вкладки (слева на десктопе, сверху на мобильном). Поля строятся рекурсивно по схеме (`components/admin/fields.tsx`).
- Переводимые поля - три строки QAZ/RUS/ENG; незаполненный перевод подсвечивается, если другие языки заполнены.
- Списки: добавить, удалить (с подтверждением), переставить стрелками; вложенные списки (группы → пункты, устройство → фото).
- Фото: загрузка сразу в Storage через server action; в браузере фото уменьшается (до 1920 px, аватары до 900 px) и пережимается в JPEG/WebP. Каждое фото - новый файл `uploads/YYYY-MM/<uuid>.<ext>` (CDN не показывает старую версию).
- Сохранение одной кнопкой (или Ctrl/⌘+S): `saveDocumentAction(id, …)` проверяет id (шаблон, портал или id из карты), нормализует данные `coerce` по схеме документа, пишет в Supabase, вызывает `updateTag('site-content')` - сайт обновляется сразу. Если строки ещё нет - создаётся черновиком.

## Надёжность

- **Одновременные правки**: сохранение идёт с `updated_at`, с которым редактор открыл данные. Если кто-то сохранил раньше - диалог «Обновить страницу / Перезаписать моими».
- **Истекла сессия**: несохранённые правки кладутся в `sessionStorage` (ключ на документ), после повторного входа предлагается их восстановить.
- Смена статуса сдвигает `updated_at`; редактор берёт новую версию из ответа, иначе следующее сохранение увидело бы «конфликт».
- Предупреждение браузера при уходе со страницы с несохранёнными изменениями.
- Если автопинг базы не срабатывал больше 48 ч - предупреждение вверху ([[keep-alive]]).
- Каждое сохранение оставляет прежнюю версию в `site_content_history` (см. [[content-model]] - откат).
